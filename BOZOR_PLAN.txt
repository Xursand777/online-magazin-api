─── BUG #1: find_user_by_phone NOANIQ NATIJA ────────────────────────────────

  MUAMMO:
    backend/users/utils.py dagi find_user_by_phone funksiyasi:
        return User.objects.filter(phone__in=phone_lookup_variants(phone)).first()
    Telefon raqami uchun 3 ta format variant qaytaradi:
        "+998901234567", "998901234567", "901234567"
    Agar bazada ikki yozuv bo'lsa (masalan, eski va yangi format):
        User A: phone="+998901234567" (admin)
        User B: phone="901234567"     (eski format, oddiy mijoz)
    .first() har xil natijani qaytaradi (DB tartibi belgisiz).
    Siz raqamingizni kiritganda BOSHQA foydalanuvchi sifatida kirib qolishingiz
    mumkin edi — bu sizning Telegram'da tasvirlagan asosiy muammo.

  YECHIM:
    backend/users/utils.py: yangi 3 bosqichli algoritm:
      1. Telefonni canonical formatga (+998XXXXXXXXX) keltir
      2. EXACT match orqali qidir → topilsa qaytar (98% holat)
      3. Topilmagandagina legacy format variantlarini ko'r:
         a) Canonical formatlilarini afzal ko'r
         b) Hali ham bir nechta bo'lsa — eng eski qayd (pk asc) ni tanla
         c) Logger orqali ogohlantirish — adminga duplicate xabar berish

  NIMA UCHUN MUHIM:
    Login = shaxs identifikatsiyasi. Noto'g'ri foydalanuvchi sifatida
    kirish = umumiy maxfiylik buzilishi + biznes obro'si yo'qotilishi.



─── BUG #2: CookieLogoutView MOBILE'NI QO'LLAB-QUVVATLAMAYDI ────────────────

  MUAMMO:
    backend/users/views.py::CookieLogoutView faqat cookie'dan refresh
    tokenni o'qiy olardi. Mobile ilova esa refresh tokenni body'da yuboradi
    (httpOnly cookie mobile'da ishlamaydi).
    Natija: mobile logout chaqirsa, refresh token serverda blacklist'ga
    QO'YILMAS edi. Token 7 kun yaroqli qolardi.

  YECHIM:
    backend/users/views.py: CookieLogoutView endi avval body'dan,
    keyin cookie'dan o'qiydi. Mobile ham, web ham logout qila oladi.

  NIMA UCHUN MUHIM:
    Telefon o'g'irlansa, foydalanuvchi "chiqdim" deb hisoblaydi — lekin
    o'g'ri qo'lidagi token 7 kun yaroqli. Bu yopilgan teshik endi
    yopildi.



─── BUG #3: MOBILE LOGOUT TO'LIQ EMAS EDI ───────────────────────────────────

  MUAMMO:
    bozor_mobile/.../auth_bloc.dart::_onLogout faqat SecureStorage'dagi
    tokenlarni tozalardi. Quyidagilar tozalanmasdi:
      • Serverga signal yuborilmasdi (refresh token blacklist bo'lmasdi)
      • CartBloc state'i (singleton — eski mahsulotlar)
      • AdminBloc state'i (singleton — eski admin ma'lumotlari)
      • Hive cartBox (eski savatcha)
      • Hive searchHistoryBox (eski qidiruv tarixi)

    Natija: admin A logout → admin B kirsa, eski admin A ma'lumotlarini
    qisman ko'rardi. Bu sizning ikkinchi muammo edi.

  YECHIM:
    Yangi: bozor_mobile/.../auth_repository.dart::logoutOnServer()
      → POST /api/auth/logout/ body bilan
    Yangi: bozor_mobile/.../local_storage.dart::clearAllUserData()
      → Hive cart va search history tozalash
    Yangi: bozor_mobile/.../cart_bloc.dart::ResetCart event
      → singleton state'ni reset qilish
    Yangi: bozor_mobile/.../admin_bloc.dart::ResetAdminData event
      → singleton state'ni reset qilish
    O'zgarish: auth_bloc.dart::_purgeAllSessionData() — barchasini birdan
    bajaradigan universal helper. _onLogout va _onForceLogout ikkalasi
    ham shu helper'ni chaqiradi.

  NIMA UCHUN MUHIM:
    "Logout = toza varaq" tamoyili. Aks holda foydalanuvchilar bir-birining
    ma'lumotlarini ko'radi — bu maxfiylik buzilishi va GDPR-style
    qoidalarga zid.



─── BUG #4: SINGLETON BLOC'LAR LOGOUT'DAN KEYIN ESKI HOLATDA QOLISHI ────────

  MUAMMO:
    bozor_mobile/.../injection_container.dart da CartBloc va AdminBloc

  YECHIM:
